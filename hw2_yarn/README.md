# ДЗ 2. Развёртывание YARN и публикация веб-интерфейсов

YARN поверх HDFS из ДЗ 1 и публикация интерфейсов демонов наружу. Параметры в ../inventory.env.

    team-09-nn   ResourceManager (UI 8088, RPC 8030-8033), NodeManager (UI 8042)
    team-09-00   NodeManager (UI 8042)
    team-09-01   NodeManager (UI 8042), JobHistory Server (UI 19888, RPC 10020)
    team-09-en   клиент yarn/mapred, nginx с публикацией интерфейсов

## Конфигурация

yarn.resourcemanager.hostname = team-09-nn, остальные адреса ResourceManager строятся от имени узла, поэтому он слушает только внутренний IP.

Ресурсы под узлы 3 ГБ и 2 vCPU: 1536 МБ и 2 vcore на NodeManager, контейнеры 256-1536 МБ, контейнеры MapReduce по 512 МБ с -Xmx410m. Проверка виртуальной памяти выключена, на таких узлах она ложно убивает контейнеры.

Логи контейнеров агрегируются в HDFS в /app-logs и смотрятся через JobHistory, история задач в /mr-history.

## Публикация интерфейсов

Внешний IP есть только у edge-ноды, демоны слушают внутренние адреса узлов. На edge ставится nginx и проксирует каждый интерфейс на отдельный внешний порт. Карта публикации задаётся в inventory.env массивом UI_ENDPOINTS, конфигурация nginx генерируется из него.

    http://171.22.73.198/                        список всех интерфейсов
    http://171.22.73.198:9870/dfshealth.html     NameNode
    http://171.22.73.198:9868/status.html        Secondary NameNode
    http://171.22.73.198:9864/datanode.html      DataNode team-09-nn
    http://171.22.73.198:9865/datanode.html      DataNode team-09-00
    http://171.22.73.198:9866/datanode.html      DataNode team-09-01
    http://171.22.73.198:8088/cluster            ResourceManager
    http://171.22.73.198:8042/node               NodeManager team-09-nn
    http://171.22.73.198:8043/node               NodeManager team-09-00
    http://171.22.73.198:8044/node               NodeManager team-09-01
    http://171.22.73.198:19888/jobhistory        JobHistory

NodeManager и DataNode трёх узлов слушают одинаковые внутренние порты, поэтому внешние разведены: 8042-8044 и 9864-9866.

Одного проксирования мало. Интерфейсы Hadoop ссылаются друг на друга по внутренним адресам: на странице ResourceManager ссылка на NodeManager ведёт на team-09-nn:8042, на странице NameNode ссылки на блоки - на team-09-00:9864. Снаружи эти имена не резолвятся и переходы между страницами ломаются. Поэтому в каждом location стоит sub_filter, который подменяет внутренние host:port на внешние адреса. Чтобы подмена работала, с upstream запрашивается несжатый ответ, а proxy_redirect приводит перенаправления к внешнему адресу. Проверка отдельно убеждается, что внутренние host:port в опубликованной выдаче ResourceManager не остались.

## Ограничение площадки

Фаервол площадки пропускает снаружи только TCP 22. Проверка с внешней машины:

    $ curl -sS -m 6 http://171.22.73.198:9870/
    curl: (28) Operation timed out after 6005 milliseconds with 0 bytes received
    $ curl -sS -m 6 http://171.22.73.198:22/
    curl: (1) Received HTTP/0.9 when not allowed

Порт 22 отвечает, остальные уходят в таймаут. На самих узлах фильтрации нет: ufw выключен, цепочки iptables пустые с политикой ACCEPT. Значит порты режутся на стороне площадки, вне доступа пользователя team.

Публикация настроена и работает, все интерфейсы отдают 200 на внешнем интерфейсе edge-ноды. Чтобы они открывались из интернета, администратору стенда нужно разрешить входящие TCP 80, 8042-8044, 8088, 9864-9866, 9868, 9870, 19888.

Пока порты не открыты, доступ с любой машины через единственный открытый порт:

    EDGE_KEY=~/.ssh/ваш_ключ ./hw2_yarn/scripts/connect_ui.sh

Скрипт поднимает проброс всех опубликованных портов на localhost и SOCKS5-прокси. Проверено с внешней машины:

    $ ssh -f -N -L 19870:127.0.0.1:9870 team@171.22.73.198
    $ curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:19870/dfshealth.html
    200

## Запуск

HDFS из ДЗ 1 должен быть запущен.

    ./hw2_yarn/scripts/deploy_yarn.sh

Или по шагам:

01_configure_yarn.sh - генерирует yarn-site.xml и mapred-site.xml, рассылает на узлы, создаёт локальные каталоги NodeManager.
02_start_yarn.sh - создаёт каталоги в HDFS и запускает ResourceManager, NodeManager, JobHistory Server.
03_publish_ui.sh - ставит nginx на edge, генерирует конфигурацию проксирования и страницу со ссылками, включает сайт.
04_verify_yarn.sh - проверка кластера и публикации.
05_check_external.sh - запускается с внешней машины, проверяет доступность опубликованных адресов из интернета.
connect_ui.sh - запускается с внешней машины, проброс портов и SOCKS-прокси через edge.
stop_yarn.sh - останавливает демоны YARN.
unpublish_ui.sh - отключает публикацию интерфейсов.

## Проверка

    ./hw2_yarn/scripts/04_verify_yarn.sh

Скрипт проверяет состояние NodeManager, доступность всех интерфейсов во внутренней сети и через nginx, отсутствие внутренних адресов в опубликованной выдаче, адреса прослушивания ResourceManager, выполняет тестовую задачу MapReduce, находит её в JobHistory и считает ERROR/FATAL в логах.

## Про доступ

Интерфейсы публикуются без аутентификации, так поставлена задача. В реальном контуре перед ними ставят ограничение по адресам, basic-аутентификацию или доступ только через VPN: страницы NameNode и ResourceManager позволяют смотреть дерево HDFS, конфигурацию кластера и jmx с внутренними адресами узлов.
